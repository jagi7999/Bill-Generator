If an uploaded QR exists it is used. Otherwise a QR is generated from the UPI ID and includes the receipt amount.

Bill data feeder — target system

Built-in mode keeps every receipt and its bill file in this browser, organised by flat, and shows them in the Feeder tab. Nothing leaves this computer, and other devices cannot send data to it. Use Export ZIP regularly as your backup; use Remote API mode to collect from several devices.
Edit the default values above with your own. Create the token with turso db tokens create <db-name>. Tables receipts and flats are created automatically on the first sync.
Each receipt is sent as a POST containing flat, owner, mobile, amount, payment mode/reference, purpose, receipt no. and the bill file. The target must be an API/webhook that accepts these and allows requests from this page (CORS). Credentials are stored in this browser only — use a limited-scope token or API key, not a personal login.

Security & backup

Data lives in this browser only. Take regular backups, and keep the file on the office computer that staff use. PINs only separate roles on a shared computer — they are not strong security.

Receipt font style & size — preview before applying

Changes are only shown in the preview until you click Apply. Fonts load from Google Fonts (internet needed the first time; if one cannot load, a similar system font is used). Kannada text uses Noto Sans Kannada.

Seal “Sealed by President”

The seal shows the date and time the receipt was saved (or last edited). Everything else on the receipt can be edited by admin, so the seal time lets you see when a bill was last changed.
